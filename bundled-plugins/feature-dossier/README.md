# Bundled Feature dossier

Increment 93 (REQ-220, DD-059). One custom view, **Feature dossier**, that answers "what is feature X about?" from the public `project@1` and `physical@1` models only. It uses plugin API 0.2 and custom API version 1 session state; Specular's core is unchanged.

- **Picker.** Configured features in configuration order with their ID counts. The selection, expanded IDs, and collapsed sections are kept in session state. A removed feature falls back to "Choose a feature".
- **Membership.** An ID belongs to a feature when its `features` assignment lists it. A feature conflict (duplicate definitions with different memberships) belongs to every feature its evidence names and is marked. Features are assigned to definitions, so an ID that is only mentioned is not a member; it appears as a link target marked "not defined".
- **Summary.** ID counts per category, an authored-status bar in the configured status colours (no status and status conflicts shown separately), and counts of feature conflicts and duplicates.
- **Categories.** Sections by role (requirement, design, task, then categories without a role), then configuration order; IDs in natural order (`T2` before `T10`).
- **Excerpts.** The defining line and the block below it (blank lines after a heading are skipped), up to the next blank line or heading, at most 12 lines, marked when truncated. Each duplicate definition has its own excerpt.
- **Links.** IDs linked in either direction from `relationships`, split into this feature and other features or IDs, with direction (→ mentions, ← mentioned by, ↔ both) and mention counts. A link inside the feature reveals that ID; one outside opens its definition.
- **Dates and files.** The five newest dated statuses and events owned by the feature's IDs, and the files that define them with counts. Every excerpt, link, date, and file opens its source.

- **Generated summary (1.1.0, increment 94b).** With custom API version 2 and `summary.generate`, a collapsible section below the summary card asks Specular's summary service for the feature (`{ kind: 'feature', key }`). Its header shows **Out of date**, **None yet**, or **Generating…** while collapsed, and the collapsed state is kept in session state. **Generate summary** (agent and optional model, kept in session state) asks once per project for consent, then shows the text labelled "Generated by <agent> on <date> from the recorded specifications. Not recorded content." Citations of the feature's IDs reveal them; citations of other defined IDs open their definitions; citations naming no project ID stay plain and are counted. When the feature changed since generation, **Out of date** says what changed (IDs added or removed, titles, statuses, definitions); the text stays until **Regenerate**. **Cancel** stops a run, and a failed or cancelled run keeps the previous summary. Nothing is generated automatically.

Everything else shown is recorded in the specifications; statuses are authored, not verified progress, and the view infers nothing that is not written.

Build independently like the Project map (`bundled-plugins/relationships`): install a locally packed `@specular/plugin-api`, TypeScript, and esbuild, then run `npm run build` and `npm run validate`. `npm run test:sdk` in Specular checks this independent build. The application build places the package under `dist/bundled-plugins/feature-dossier`.
